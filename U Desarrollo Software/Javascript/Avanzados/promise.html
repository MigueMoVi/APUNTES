Promise

Una Promesa (Promise) es un proxy de un valor que no necesariamente se conoce cuando se crea la promesa.
Le permite asociar controladores con el valor eventual de éxito o el motivo de falla de una acción asíncrona.
Esto permite que los métodos asíncronos devuelvan valores como los métodos síncronos: en lugar de devolver inmediatamente el valor final, el método asíncrono devuelve la promesa de proporcionar el valor en algún momento en el futuro.

En otras palabras, una promesa es un objeto que maneja operaciones asíncronas

"I promise to return a value"
PENDING -> RESOLVED or REJECTED

const myPromise = new Promise( (resolve, reject) => {asynchronous code} )

Luego para el flujo dependiendo si funciona o no es:

	myPromise
		.then( [funcionó A], [no funcionó A] )
		.then( [funcionó B], [no funcionó B] )
		.then( [funcionó C], [no funcionó C] );

Primero se ejecuta A, luego B y finalmente C

Una promesa se encuentra en uno de los 3 estados:

  • pending (pendiente) : estado inicial, ni cumplido ni rechazado.
  • fulfilled (cumplida) : lo que significa que la operación se completó con éxito.
  • rejected (rechazada) : lo que significa que la operación falló.

Por ejemplo 

const myPromise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("foo");
  }, 300);
});

myPromise
  .then(handleResolvedA, handleRejectedA)
  .then(handleResolvedB, handleRejectedB)
  .then(handleResolvedC, handleRejectedC);
  1. Creación de la Promesa
    • Creas una operación asíncrona simulada con setTimeout.
    • Después de 300 milisegundos, la promesa se cumple con éxito invocando a resolve("foo"). Esto significa que el valor inicial que viaja por la cadena es el texto "foo".
  2. El Encadenamiento (.then)
    • Cada .then() recibe dos funciones como argumentos: la primera se ejecuta si la promesa anterior se cumplió y la segunda si fue rechazada o lanzó un error.
    • Paso A: Como myPromise se resuelve con "foo", se ejecuta handleResolvedA("foo"). El resultado que devuelva esta función se pasará automáticamente como argumento al siguiente bloque.
    • Paso B: Si handleResolvedA se ejecuta correctamente y devuelve un valor, se llamará a handleResolvedB(valorAnterior).
    • Paso C: De igual manera, lo que devuelva handleResolvedB se le pasará a handleResolvedC(valorAnteriorB).
  3. ¿Qué pasa si hay un error (Rechazo)?
    • Si en alguno de los pasos ocurre un error o la función devuelve una promesa rechazada, se saltará el flujo feliz.
    • Se ejecutará el manejador de errores del siguiente bloque (por ejemplo, handleRejectedB).
    • Si el manejador resuelve el error correctamente devolviendo un valor normal, la cadena se recupera y el siguiente paso ejecutará su función de éxito (handleResolvedC).

Con manejo de errores: 

	myPromise
		.then( [funcionó A], [no funcionó A] )
		.then( [funcionó B], [no funcionó B] )
		.then( [funcionó C], [no funcionó C] )
		.catch( (error) => console.log(error) );

Ejemplo

Haga las siguientes tareas en orden:
1. Pasear al perro
2. Limpiar la cocina
3. Botar la basura

La funciones por defecto serían 

	// FUNCIONES ORIGINALES
	function walkDog(){
		setTimeout( () => {
					console.log("Ya has paseado al perro");
				}
		, 1500);
	}
	function cleanKitchen(){
		setTimeout( () => {
					console.log("Limpiaste la cocina");
				}
		, 2500);
	}
	function takeOutTrash(){
		setTimeout( () => {
					console.log("Botaste la basura");
				}
		, 500);
	}

Usando callbacks porque haremos las tareas en orden

	// Si quisiéramos hacer estas tareas en orden, tendríamos que usar callbacks
	function walkDog(callback){
		setTimeout( () => {
						console.log("Has paseado al perro (1)" );
						callback();
					}
		, 1500);
	}
	
	function cleanKitchen(callback){
		setTimeout( () => {
						console.log("Has limpiado la cocina (2)");
						callback();
					}
		, 2500);
	}
	
	function takeOutTrash(callback){
		setTimeout( () => {
						console.log("Has botado la basura (3)");
						callback();
					}
		, 500);
	}
	
	
	// Y luego ejecutar
	walkDog( () => {
			cleanKitchen( () => {
				takeOutTrash( () => console.log("Has terminado todas las tareas"));
		});
	});

Pero esta no es una buena práctica, ya que si fueran más tareas esto crecería y formaría un callback hell


Usando promesas

Usaremos method chaining. Cómo podemos modificar estas funciones para que al final retorne un objeto (Promesa) 

	function walkDog(){
		return new Promise( (resolve, reject) => {
			setTimeout( () => {
						// resolve es una funcióN
						// DEVOLVERÁ ESTE VALOR
						resolve( "Has paseado al perro (1)" );
						}
			, 1500);
		});
		
	}
	
	function cleanKitchen(callback){
		return new Promise( (resolve, reject) => {
			setTimeout( () => {
						// resolve es una función
						resolve( "Has limpiado la cocina (2)" );
						}
			, 1500);
		});
	}
	
	function takeOutTrash(callback){
		return new Promise( (resolve, reject) => {
			setTimeout( () => {
						// resolve es una función
						resolve( "Has botado la basura (3)" );
						}
			, 1500);
		});
	}

NOTE QUE SOLO SE PASA EL PARÁMETRO resolve


Manejando errores

Usando el ejemplo anterior 

function walkDog(){
	return new Promise( (resolve, reject) => {
		setTimeout( () => {
					const dogwalked = true/false;
					
					if (dogwalked){
						resolve( "Has paseado al perro (1)" );
					}
					else{
						reject(" No has paseado al perro");
					}
					
				}
		, 1500);
	});
	
}

// Ejecución
walkDog()
	.then( value => console.log(value) )
	.catch( (error) => console.log(error));

En este caso vamos a obtener cualquiera de los dos mensajes como string dependiendo del valor del booleano (resaltado en rojo)
